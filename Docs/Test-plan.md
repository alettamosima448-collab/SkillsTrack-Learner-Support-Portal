# Learner Support Portal - Test Plan

## 1. Introduction

The purpose of this test plan is to explain how the Learner Support Portal will be tested.

Testing will help the team find mistakes and make sure that the portal works correctly and is easy for learners to use.

## 2. Purpose of Testing

The purpose of testing is to:

- Check that the features of the portal work correctly.
- Find errors or problems in the system.
- Make sure learners can use the portal easily.
- Make sure information is saved and displayed correctly.
- Make sure the system meets the project requirements.

## 3. Features to be Tested

The following features will be tested:

### 3.1 Learning Tasks

The team will test whether learners can:

- View their learning tasks.
- Add learning tasks if this feature is included.
- Manage their learning tasks.
- Mark tasks as completed if this feature is included.

### 3.2 Learner Support Bookings

The team will test whether learners can:

- Access the learner support section.
- Make a support booking if this feature is included.
- View their support bookings.
- Check that booking information is displayed correctly.

### 3.3 Learning Progress

The team will test whether learners can:

- View their learning progress.
- See accurate progress information.
- See changes to their progress when information is updated.

### 3.4 User Interface

The team will test whether:

- Pages display correctly.
- Buttons work correctly.
- Information is easy to understand.
- Navigation between pages works.
- The portal is simple for learners to use.

## 4. Types of Testing

### 4.1 Functional Testing

Functional testing will check whether each feature performs the task it is supposed to perform.

For example, if a learner clicks a button to view their tasks, the correct tasks should be displayed.

### 4.2 Usability Testing

Usability testing will check whether the portal is easy for learners to understand and use.

### 4.3 User Interface Testing

User interface testing will check that buttons, forms, menus and pages work and display correctly.

### 4.4 Data Testing

Data testing will check that learner information is correctly saved, retrieved and displayed.

## 6. Expected Results

The expected result is that all important features of the Learner Support Portal work correctly and that learners can use the system without unnecessary difficulty.

Any problems found during testing will be recorded and reported to the development team.

## 7. Recording Problems

When a problem is found, the team should record:

- What went wrong.
- Where the problem occurred.
- The steps taken before the problem happened.
- What was expected to happen.
- What actually happened.
- Whether the problem has been fixed.

## 8. Test Status

The following statuses can be used:

- **Not Tested** - The test has not been completed.
- **Pass** - The feature worked as expected.
- **Fail** - The feature did not work as expected.
- **Needs Retesting** - The problem was fixed and needs to be tested again.

## 9. Conclusion

Testing will help the team make sure that the Learner Support Portal works correctly and meets the needs of its learners.

The test plan will be updated as the project develops and new features are added.
